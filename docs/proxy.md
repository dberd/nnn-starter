# Прокси и корпоративный VPN: как этим пользоваться

Документ про повседневную работу: что нажимать, что проверять, как добавить ноду и куда
смотреть, когда что-то не работает. Почему всё устроено именно так — в комментариях модулей
и в сообщениях коммитов, здесь этого нет.

Состояние на 22.08.2026: Throne **ещё установлен и работает**, его TUN накрывает весь трафик
машины. sing-box поднят рядом как локальный прокси и пока обслуживает только тех, кто в него
явно ходит. Порядок сноса Throne — в конце документа.

---

## 1. Что где живёт

| Файл | Что описывает |
|---|---|
| `modules/nixos/singbox.nix` | ядро: ноды, селектор, маршруты, DNS, Clash API |
| `modules/home/noctalia.nix` | виджет в баре: плагин `mihomo-control` и патч к нему |
| `modules/nixos/vpn.nix` | snx-rs, split-routing, обход nftables-перехвата Throne |
| `secrets/secrets.yaml` | ключи нод и профиль snx (sops) |

Порты:

| Порт | Чей | Что |
|---|---|---|
| `127.0.0.1:2081` | sing-box | mixed-инбаунд: один порт говорит и SOCKS, и HTTP |
| `127.0.0.1:9091` | sing-box | Clash API — с ним разговаривает виджет |
| `127.0.0.1:2080` | Throne | его инбаунд, пока он жив |
| `throne-tun` | Throne | его TUN, пока он жив |

## 2. Виджет

Иконка щита с замком в баре, между раскладкой и сетью. Цвет — состояние контроллера:
живой sing-box зелёный, недоступный красный.

- **левый клик** — открыть панель;
- **средний клик** — настройки виджета (что показывать рядом с иконкой: режим, трафик,
  число соединений, текущая нода, задержка).

В панели:

| Кнопка | Что делает |
|---|---|
| нода в списке | переключить. Старые соединения рвутся намеренно, иначе переключение выглядит как «не сработало» |
| **Test all** | замерить задержку всех нод разом |
| **Rule / Global / Direct** | режим маршрутизации, см. ниже |
| **Restart** | **не работает.** sing-box не реализует `POST /restart` и отвечает 404. Перезапуск — `systemctl restart sing-box` |

Плитка в центре управления переключает только **Rule ↔ Global**; Direct — из панели.

---

## 3. Режимы

| Режим | Что уходит в ноду | Когда нужен |
|---|---|---|
| **Rule** (по умолчанию) | всё, кроме приватных сетей и `*.efko.ru` | обычная работа, в том числе с корпоративным VPN |
| **Global** | **всё**, включая корпоративное | когда нужно накрыть прокси абсолютно всё. Работу с `efko.ru` это ломает |
| **Direct** | ничего | проверить, виноват ли прокси |

Режим не переживает перезапуск sing-box — как и выбранная нода. Это намеренно: `cache_file`
не включён, поэтому после `systemctl restart sing-box` система возвращается в состояние,
описанное в репозитории (`default = vavn-fr-hy2`, режим `Rule`).

---

## 4. Что вообще идёт через прокси

sing-box у нас — **локальный прокси, а не TUN**. Через него идёт только то, что само туда
обращается. Пока работает Throne, разницы не видно: его TUN заворачивает всё.

Направить приложение в наш прокси:

```fish
set -x HTTPS_PROXY http://127.0.0.1:2081
set -x ALL_PROXY   http://127.0.0.1:2081
set -x NO_PROXY    localhost,127.0.0.1,.efko.ru,10.0.0.0/8,192.168.0.0/16
```

`NO_PROXY` обязателен: без него корпоративные имена уедут в ноду и не найдутся. Приём уже
применён в обёртке `claude` (`modules/home/claude-code.nix`).

## 5. Корпоративный VPN

```fish
snxctl connect      # спросит 2FA
snxctl status
snxctl disconnect
```

Правила маршрутизации подхватываются **сами**: `snx-vpn-routing-trigger.service` привязан к
device-юниту `snx-tun`, поэтому каждое подключение перестраивает и таблицу 18000, и обход
Throne. Руками ничего перезапускать не нужно.

Проверка, что корпоративная сеть жива:

```fish
host gitlab.sddt.efko.ru 10.47.1.1        # -> dt-revproxy.efko.ru -> 10.52.12.34
git ls-remote https://gitlab.sddt.efko.ru/committees/backend.git | head -1
```

## 6. Добавить или обновить ноду

Подписок у sing-box нет — список нод живёт в репозитории, и это осознанный размен:
воспроизводимость против автообновления. Порядок:

1. взять ссылку ноды (`vless://…`, `hy2://…`) или обновить подписку в Throne и вынуть
   `outbound_json` из `~/.config/Throne/config/throne.db`, таблица `profiles`;
2. положить ключи в sops:

   ```fish
   nix develop
   sops secrets/secrets.yaml
   ```

3. добавить outbound в `modules/nixos/singbox.nix`, сославшись на секрет через
   `{_secret = config.sops.secrets.<имя>.path;}`, и вписать его тег в список селектора;
4. проверить конфиг до применения:

   ```fish
   nix eval --json .#nixosConfigurations.nnn-desktop.config.services.sing-box.settings \
     | jq 'walk(if type == "object" and has("_secret") then "x" else . end)' > /tmp/sb.json
   sing-box check -c /tmp/sb.json
   ```

5. `sudo nixos-rebuild switch --flake .#nnn-desktop` — нода появится в панели.

Что sing-box умеет: VLESS, VMess, Trojan, Shadowsocks, TUIC, Hysteria2, WireGuard, SSH,
с REALITY и uTLS. Чего не будет: импорта подписки одной ссылкой и автообновления ключей —
если провайдер их ротирует, нода молча умирает и чинится руками.

## 7. Диагностика

```fish
# ядро живо и слушает
systemctl status sing-box
ss -tlnp | grep -E '2081|9091'

# какая нода выбрана и что вообще есть
curl -s http://127.0.0.1:9091/proxies | jq '.proxies.proxy | {now, all}'

# задержки
curl -s 'http://127.0.0.1:9091/group/proxy/delay?url=http%3A%2F%2Fcp.cloudflare.com&timeout=5000'

# куда мы выходим через прокси
curl -s -x http://127.0.0.1:2081 https://ifconfig.me

# корпоративное идёт мимо прокси и через туннель
curl -s -o /dev/null -w '%{http_code}\n' -x http://127.0.0.1:2081 https://gitlab.sddt.efko.ru/

# обход Throne считает пакеты (пока Throne жив)
sudo nft list chain inet snx-bypass output_mark | grep counter

# логи
journalctl -u sing-box -n 50
rg -i 'luau|plugin-service' ~/.cache/noctalia/noctalia.log | tail
```

Если виджет показывает прочерки — сначала `systemctl status sing-box`, потом
`ss -tnp | grep 9091` (шелл должен держать соединения с API), потом лог шелла.

---

## 8. Откат

```fish
sudo nixos-rebuild switch --rollback
systemctl --user restart noctalia          # если дело в баре
```

Состояния на диске у этой связки нет: конфиг Noctalia — read-only симлинк в стор,
конфиг sing-box собирается заново при каждом старте службы. Поэтому откат поколения
возвращает ровно то, что было.

## 9. Что осталось сделать

**Снос Throne** — двумя отдельными rebuild'ами, порядок важен:

1. `modules/home/claude-code.nix`: `proxyPort` с `2080` на `2081`. Через инбаунд Throne
   ходит Claude Code, и если выключить Throne первым, он потеряет сеть в самый неподходящий
   момент;
2. `programs.throne.enable = false`. Вместе с ним из `vpn.nix` уезжает обход nftables: без
   TUN Throne там ничего не остаётся, и корпоративные исключения полностью переходят к
   правилам внутри sing-box. После этого обязательно перепроверить раздел 5.
3. Заодно: Clash API можно вернуть на привычный 9090, а `inboundPort` — на 2080.

**Решение про охват.** После сноса Throne системный трафик перестанет заворачиваться
автоматически. Либо прописывать 2081 приложениям (точечно, корпоративный трафик вне игры),
либо включать TUN у sing-box (накрывает всё, но возвращает историю с nftables — уже под
нашим контролем).

**Французская REALITY-нода** в конфиг не входит: сервер не принимает её ключи — проверено
и под sing-box, и под Xray-core 26.3.27, который носит внутри себя Throne. Если провайдер
обновит подписку, ноду можно вернуть по разделу 6.
