# Прокси и корпоративный VPN: как этим пользоваться

Документ про повседневную работу: что нажимать, что проверять, как добавить ноду и куда
смотреть, когда что-то не работает. Почему всё устроено именно так — в комментариях модулей
и в сообщениях коммитов, здесь этого нет.

Состояние на 22.08.2026, финальное: Throne **остаётся насовсем** — его TUN накрывает весь
трафик машины и это единственное, что реально покрывает игры/Steam (прокси-настройки они не
читают, а UDP-мультиплеер через SOCKS/HTTP в принципе не проксируется). Попытка перевести
покрытие на TUN самого sing-box (22.08, тот же день) провалена и не повторяется — постмортем
в разделе 9. sing-box рядом остаётся локальным прокси для того немногого, что явно указывает
на него (Claude Code) и для ручного выбора ноды через CLI, независимо от того, что в данный
момент делает Throne.

**Throne — не служба.** Обычное приложение (`Throne` + `ThroneCore`), запускается и
останавливается руками через его собственный значок в системном трее или
`pkill -f 'share/throne/Throne'`. Автостарта нет — попытка (23.08, `systemd.user.services`)
испробована и отменена, постмортем в разделе 9 — после релогина/ребута запускать заново самому.

## 1. Что где живёт

| Файл | Что описывает |
|---|---|
| `modules/nixos/singbox.nix` | ядро: ноды, селектор, маршруты, DNS, Clash API |

Порты:

| Порт | Чей | Что |
|---|---|---|
| `127.0.0.1:2081` | sing-box | mixed-инбаунд: один порт говорит и SOCKS, и HTTP |
| `127.0.0.1:9091` | sing-box | Clash API — с ним разговаривает CLI |
| `127.0.0.1:2080` | Throne | его инбаунд |
| `throne-tun` | Throne | его TUN — весь трафик машины, включая игры/Steam |

## 2. Управление: CLI

Bar-виджета (`mihomo-control`) больше нет — убран 23.08 вместе со всем патчем в
`noctalia.nix`: он давал только визуальный статус и "Test all", а sing-box к тому моменту уже
обслуживал только Claude Code — сфера слишком узкая, чтобы держать ради неё четыре патча под
конкретную версию luau конкретной сборки Noctalia. Постмортем — раздел 9.

Три fish-функции в `modules/home/fish.nix`, никакой зависимости от Noctalia/niri, работают на
любом хосте, где поднят sing-box:

```fish
function proxy-node
    curl -s -X PUT http://127.0.0.1:9091/proxies/proxy \
        -d (printf '{"name":"%s"}' $argv[1]) >/dev/null
end

function proxy-mode
    curl -s -X PATCH http://127.0.0.1:9091/configs \
        -d (printf '{"mode":"%s"}' $argv[1]) >/dev/null
end

function proxy-status
    curl -s http://127.0.0.1:9091/proxies/proxy | jq '{now, all}'
end
```

Использование: `proxy-node vavn-lv`, `proxy-mode Global`, `proxy-status`. Названия нод и
режимов — как в `singbox.nix` (`vavn-lv`, `vavn-fr-hy2`, `direct`; `Rule`/`Global`/`Direct`).

## 3. Режимы

| Режим | Что уходит в ноду | Когда нужен |
|---|---|---|
| **Rule** (по умолчанию) | всё, кроме приватных сетей и `*.efko.ru` | обычная работа, в том числе с корпоративным VPN |
| **Global** | **всё**, включая корпоративное | когда нужно накрыть прокси абсолютно всё. Работу с `efko.ru` это ломает |
| **Direct** | ничего | проверить, виноват ли прокси |

Режим не переживает перезапуск sing-box — как и выбранная нода. Это намеренно: `cache_file`
не включён, поэтому после `systemctl restart sing-box` система возвращается в состояние,
описанное в репозитории (`default = vavn-fr-hy2`, режим `Rule`).

## 4. Что вообще идёт через прокси

Два независимых пути, и они не пересекаются:

| | Что покрывает | Как переключить ноду |
|---|---|---|
| **Throne (TUN)** | всё остальное: игры, Steam, браузер, обычный git — весь трафик машины без исключений | только в самом Throne, его UI/трей |
| **sing-box (локальный прокси)** | только то, что явно на него указывает — сейчас это Claude Code | `proxy-node`/`proxy-mode` (раздел 2) |

sing-box — **локальный прокси, а не TUN**: через него идёт только то, что само туда
обращается. Раньше (пока не было решено оставить Throne насовсем) казалось, что это временная
мера на время его отсутствия — теперь это осознанное разделение: Claude Code сидит на sing-box
не потому, что Throne не работает, а чтобы его путь не зависел от того, какую ноду или режим
сейчас выбрал Throne.

Направить ещё какое-то приложение в sing-box напрямую (в обход Throne):

```fish
set -x HTTPS_PROXY http://127.0.0.1:2081
set -x ALL_PROXY   http://127.0.0.1:2081
set -x NO_PROXY    localhost,127.0.0.1,.efko.ru,10.0.0.0/8,192.168.0.0/16
```

`NO_PROXY` обязателен: без него корпоративные имена уедут в ноду и не найдутся. Приём уже
применён в обёртке `claude` (`modules/home/claude-code.nix`).

## 5. Корпоративный VPN

```fish
snxctl connect      # спросит 2FA
snxctl status
snxctl disconnect
```

Правила маршрутизации подхватываются **сами**: `snx-vpn-routing-trigger.service` привязан к
device-юниту `snx-tun`, поэтому каждое подключение перестраивает и таблицу 18000, и обход
Throne. Руками ничего перезапускать не нужно.

Проверка, что корпоративная сеть жива:

```fish
host gitlab.sddt.efko.ru 10.47.1.1        # -> dt-revproxy.efko.ru -> 10.52.12.34
git ls-remote https://gitlab.sddt.efko.ru/committees/backend.git | head -1
```

## 6. Подписки и ноды

У sing-box подписок нет вообще: список нод живёт в репозитории. Это осознанный размен —
воспроизводимость против автообновления. Ниже три сценария.

### 6.1 Обновить существующую подписку

Пока Throne жив, проще всего его руками: группа `Vavn` → обновить. После этого свежие ноды
лежат в его базе, откуда их видно так (ключи не печатаются):

```fish
cd /tmp
cp ~/.config/Throne/config/throne.db* .
nix run nixpkgs#sqlite -- throne.db "select id, name, type from profiles;"
nix run nixpkgs#sqlite -- throne.db "select outbound_json from profiles;" \
  | sed -E 's/("(uuid|password|public_key|short_id)"[[:space:]]*:[[:space:]]*")[^"]*/\1***/g'
```

Без Throne — напрямую по URL подписки. Он тоже лежит в его базе (`select url from groups;`),
и его стоит забрать оттуда **до** сноса. Большинство провайдеров отдают base64-список ссылок:

```fish
curl -s "$SUB_URL" | base64 -d
```

Дальше в обоих случаях — 6.3.

### 6.2 Добавить новую подписку (другой провайдер)

Отличий от 6.1 нет: подписка — это просто список ссылок. Ноды из неё становятся такими же
outbound'ами со своими тегами, каждая со своими секретами. Держи теги говорящими и
уникальными (`vavn-lv`, `vavn-fr-hy2`) — по ним ты будешь выбирать ноду в панели.

Сам URL подписки, если он нужен на будущее, кладётся туда же, в sops, отдельным ключом —
он даёт доступ к твоим нодам и в репозитории ему не место.

### 6.3 Положить ноду в конфигурацию

1. Секреты — в sops (ключи, которые правда секретны: `uuid`, `password`, `obfs`,
   `public_key`/`short_id` у REALITY):

   ```fish
   cd ~/nixos-config
   nix develop          # приносит sops и age
   sops secrets/secrets.yaml
   ```

   Имена ключей — по образцу существующих: `singbox-<провайдер>-<что это>`.

2. Outbound — в `modules/nixos/singbox.nix`, рядом с остальными. Секретные поля пишутся не
   значением, а ссылкой:

   ```nix
   uuid = {_secret = config.sops.secrets.singbox-vavn-uuid.path;};
   ```

   И три вещи, которые легко забыть: добавить `routing_mark = bypassMark;` (иначе соединение
   уедет в чужой туннель, пока такой есть), вписать тег в список `outbounds` селектора, и
   объявить сам секрет в блоке `sops.secrets` этого же модуля.

3. Проверить **до** применения — конфиг собирается и валиден:

   ```fish
   nix eval --json .#nixosConfigurations.nnn-desktop.config.services.sing-box.settings \
     | jq 'walk(if type == "object" and has("_secret") then "x" else . end)' > /tmp/sb.json
   sing-box check -c /tmp/sb.json
   ```

4. Применить и убедиться, что нода реально работает:

   ```fish
   sudo nixos-rebuild switch --flake .#nnn-desktop
   curl -s http://127.0.0.1:9091/proxies | jq '.proxies.proxy.all'
   curl -s 'http://127.0.0.1:9091/group/proxy/delay?url=http%3A%2F%2Fcp.cloudflare.com&timeout=5000'
   ```

   Задержка `-1` или отсутствие ноды в ответе — значит сервер не принял параметры, и дальше
   смотреть `journalctl -u sing-box`.

Что sing-box умеет: VLESS, VMess, Trojan, Shadowsocks, TUIC, Hysteria2, WireGuard, SSH,
с REALITY и uTLS. Чего не будет: импорта подписки одной ссылкой, автообновления ключей и
health-check'а с автопереключением. Если провайдер ротирует ключи часто, ручной путь
становится дорогим — тогда имеет смысл вернуться к разговору про mihomo с `proxy-providers`,
ценой того, что список нод переедет из репозитория в рантайм-кэш.
## 7. Диагностика

```fish
# ядро живо и слушает
systemctl status sing-box
ss -tlnp | grep -E '2081|9091'

# какая нода выбрана и что вообще есть
curl -s http://127.0.0.1:9091/proxies | jq '.proxies.proxy | {now, all}'

# задержки
curl -s 'http://127.0.0.1:9091/group/proxy/delay?url=http%3A%2F%2Fcp.cloudflare.com&timeout=5000'

# куда мы выходим через прокси
curl -s -x http://127.0.0.1:2081 https://ifconfig.me

# корпоративное идёт мимо прокси и через туннель
curl -s -o /dev/null -w '%{http_code}\n' -x http://127.0.0.1:2081 https://gitlab.sddt.efko.ru/

# обход Throne считает пакеты
sudo nft list chain inet snx-bypass output_mark | grep counter

# логи
journalctl -u sing-box -n 50
```

Если `proxy-status` не отвечает — сначала `systemctl status sing-box`, потом
`ss -tnp | grep 9091`.

## 8. Откат и одна ловушка

```fish
sudo nixos-rebuild switch --rollback
systemctl --user restart noctalia          # если дело в баре
```

Конфиг sing-box собирается заново при каждом старте службы, а `~/.config/noctalia/config.toml`
— read-only симлинк в стор. В этой части откат поколения возвращает ровно то, что было.

**Но у Noctalia есть второй конфиг, и он сильнее.** Всё, что ты меняешь в её UI — порядок
виджетов в баре, пороги, раскладка локскрина — пишется в

```
~/.local/state/noctalia/settings.toml
```

и **перебивает** то, что описано в Nix. Файл живёт в state, а не в конфиге, поэтому его не
трогают ни rebuild, ни откат поколения. Симптом узнаваемый: правишь `bar.default.end` в
`modules/home/noctalia.nix`, применяешь — и ничего не меняется.

Вернуть контроль Nix'у — убрать перебитую секцию и перезапустить шелл:

```fish
cp ~/.local/state/noctalia/settings.toml /tmp/settings.toml.bak
awk 'BEGIN{skip=0} /^\[/{skip = ($0=="[bar.default]")} !skip' \
  ~/.local/state/noctalia/settings.toml > /tmp/settings.new
cp /tmp/settings.new ~/.local/state/noctalia/settings.toml
systemctl --user restart noctalia
```

(`[bar.default]` заменить на ту секцию, которую нужно вернуть под Nix.) Правило простое:
если настройку хочется держать в репозитории — не трогать её в UI, а если уже тронул,
вычистить её оттуда.

## 9. Постмортемы

**TUN у sing-box вместо Throne — испробовано и отклонено, 22.08.** Идея была: снести Throne,
покрыть систему TUN'ом самого sing-box (`route.auto_route`, `strict_route = false` ради
fail-open). На практике за один вечер вскрылось два независимых бага:

- `address = ["172.19.0.1/30"]` (пример-адрес из документации sing-box) совпал с адресом,
  который уже использует `throne-tun` — тот же `172.19.0.1`, только другая маска. Оба TUN
  заявили один и тот же IP одновременно.
- `ip rule` показал правило `1: from all lookup <table>` — **безусловное**, без проверки
  fwmark, впереди вообще всего, включая правила snx (`4900–5100`) и собственный
  `routing_mark` sing-box. Вопреки более раннему предположению в этом же документе,
  `routing_mark` не создаёт автоматического исключающего правила для трафика, который sing-box
  сам же генерирует — из-за этого его собственное исходящее к `fr.vavn.pro` закольцовывалось
  само в себя (`journalctl`: `lookup fr.vavn.pro: context deadline exceeded`).

Оба бага решаемы по отдельности (другой адрес; ручное `ip rule` с отрицательным приоритетом
для исключения), но это уже не "включить одну опцию", а отдельное исследование с неочевидным
результатом. Решение — не продолжать: Throne уже решал эту же задачу (TUN + snx) годом раньше,
и решал её проверенно (раздел про `snx-bypass` в `vpn.nix`). Тратить вечера на повторное
изобретение того же самого в другом движке не имеет смысла, особенно когда на кону игры,
которым нужен рабочий TUN, а не эксперимент.

**REALITY закрыт, без Xray.** Французскую REALITY-ноду не тащим. Причина измерена — `git log`
на `singbox.nix`/`vpn.nix` (`6dc00e8`): после ротации ключей провайдером нода отвечает под
Xray-core 26.3.27, но sing-box её не берёт (`reality verification failed` на 1.13.14 и 1.13.18,
с `flow` и без, оба отпечатка uTLS, `sid` исходный и пустой) — ограничение клиента, не мёртвый
сервер. Локация всё равно доступна: Hy2-нода `vavn-fr-hy2` — тот же хост. Ставить Xray-core
сайдкаром ради одной этой ноды решили не делать — второй движок ради одного протокола того не
стоит. `docs/plan-xray-reality-node.md` отменён (пометка в начале файла), исполнять не нужно.

**CLI — готово и применено.** `proxy-node`/`proxy-mode`/`proxy-status` в `modules/home/fish.nix`,
см. раздел 2.

**Виджет `mihomo-control` — убран, 23.08.** Раз sing-box теперь обслуживает только Claude
Code, а не всю систему (это делает Throne), держать четыре luau-патча под конкретную сборку
Noctalia ради визуального статуса одного узкого кейса перестало окупаться — CLI из раздела 2
делает то же самое (кроме "Test all", единственное, чего CLI не повторяет). `communityPlugins`
и связанный `flake.nix`-инпут `noctalia-community-plugins` удалены из `noctalia.nix`.

**Автостарт Throne — испробовано и отклонено, 23.08.** `systemd.user.services.throne`,
привязанный к `graphical-session.target` (по образцу того, как заведена Noctalia). После
настоящего ребута юнит стартовал штатно по логам systemd, но GUI показал ошибку
"cannot set suid for ThroneCore" — при том что `/run/wrappers/bin/ThroneCore` в этот момент уже
стоял с нужными capabilities. Причина не установлена: похоже на состояние гонки между
`security.wrappers` и первым запуском GUI, но подтвердить это значит повторить сбой на живом
соединении, а это было бы неоправданным риском. Правку откатили; рабочий обходной путь —
`throne` добавлен в `home.packages` (`modules/home/apps.nix`) и запускается вручную, как раньше.
Автостарт можно попробовать снова отдельно, без спешки и не в момент, когда Throne — единственный
путь в сеть.
